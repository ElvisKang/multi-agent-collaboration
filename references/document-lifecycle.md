# 协作文档与版本管理

按内容的有效期和可移植性分类，不只看文件名。项目可选不同目录，但应在根规范中明确唯一位置。

## 分层

| 内容 | Git | 归属 |
|---|---|---|
| 工程规则、硬件/身份约束、接续入口 | 提交 | AGENTS |
| 当前基线、已验证结论、已知问题、证据索引 | 提交 | 总 HANDOFF |
| 产品能力、里程碑、长期待办 | 提交 | PLAN |
| 任务 ID 与本机 worktree/owner/临时状态 | 本地忽略 | 本地任务表 |
| 会话 UUID、CLI 参数、实例目录、确认时间 | 本地忽略 | 本地会话路由 |
| 本轮进度、review 接力、阻塞、下一步 | 本地忽略 | 临时交接 |
| 原始日志、固件、读回、临时截图与本机证据位置 | 通常本地/外部归档 | 证据映射；确需共享的证据按项目约定另存 |
| 协作流程、消息协议、通用模板 | 提交 | 本技能及 assets/references |

任务列表若记录可共享的产品需求和验收标准，可以提交；含本机 owner/worktree 的运行登记不应混入其中。历史日期、固件 hash、板卡 ID 和测量数据可以长期有效；保留验证条件和边界，不因“有日期”删掉事实。

项目个性化配置可直接写 HANDOFF 的协作约定段，使用已有文档而非再建一套规范；机器路径、凭据和真实绑定仅写本地配置。通用角色、接力与协作改进在全局技能维护；项目的创建方法、接口/质量约束与明确要求的 TDD 理念在项目文档维护。管理者按实际效果沉淀触发条件、做法和验证方法，不把每次事故或待验证猜测升级为永久规则。

## 可移植内容

- 源码、素材、构建命令使用仓库或项目相对路径，并写明相对基准。
- 本机用户名、绝对 checkout 路径、App 安装路径、串口、私网地址、daemon 端口、profile 和会话 UUID 留在本地。文档写发现方法或配置键名，不把一次探测结果当默认值。
- 操作系统、工具版本、芯片和硬件引脚若是复现条件则保留；设备身份不因迁移设备而重写。
- 外部证据使用稳定归档 ID、文件名、hash 和验证日期；实际根目录写本地映射。说明“需另行迁移”，不把外部归档伪装成仓库内已存在文件。
- JSON 等结构化记录也检查路径字段；改变路径约定前查消费者，说明解析基准，保留测量值和原验证状态。
- 总 HANDOFF 不写“本次整理”“当前未提交文件”等易失工作区状态。项目规则引用技能，不再复制登记算法、CLI 示例或消息协议。

## 迁移与忽略

1. 先盘点已跟踪、未跟踪、已忽略及已有修改，核对引用和其他会话是否仍用旧入口。
2. 按项目约定将运行记录集中到被忽略的目录，保留原任务 ID、当前身份/绑定、未决事项、验证边界和必要证据位置；活跃会话不因迁移变成已结束。
3. 从待版本化文档移除本地内容，先沉淀长期结论。精简时只保留影响下一步决策的信息；删除重复 ACK、旧队列 ID、已解决故障和迁移流水，不默认整份归档旧文档。通用规则写技能，未决事项写任务交接，必要证据另存。模板集中到本技能，不包含真实会话或本机值。
4. 共享目录约定写项目 .gitignore；仅某台机器的例外才用 .git/info/exclude。避免 `**/session.md` 一类过宽规则误伤技能模板。
5. .gitignore 对已跟踪文件不生效。经授权移出版本管理时，将原内容迁到本地，再删除旧的已跟踪副本，作为普通删除差异待审；无需擅自修改暂存区。不要依赖 skip-worktree/assume-unchanged 隐藏改动。
6. 迁移期间旧入口可保留为本地转向指针，指向唯一新入口；不保留第二份独立运行状态。主工作区不可访问或活跃记录冲突时停下相应迁移，不猜测覆盖。
7. 验证技能、引用、Git 忽略与删除差异；确认模板可被 Git 收录，本地记录不会进入待提交内容，实际记录和字段没有丢失。

新设备缺少本地登记是正常状态；读取共享交接后按实际任务初始化，不要求先复制原机器的会话历史。
