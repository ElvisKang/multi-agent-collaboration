# MiMo 自主接力适配

仅在 MiMo 使用自身原生工具创建/联络接力会话时读取。以下依据用户提供的当前工具反馈，属于可替换适配；工具定义变化时按实际支持调整，不要求其他 Agent 实现同名方法。本文未做真实原生投递测试。

## create_session 参数与接力顺序

当前参数为 name、purpose、workspace、task，没有 model 参数：

| 字段 | 内容 |
|---|---|
| name | 规范会话标题，围绕需求与角色 |
| purpose | 角色/用途描述，是否被客户端实际使用以当前定义为准；关键职责仍写入 task |
| workspace | Git 主工作区根，实际开发 worktree 在初始任务中另写 |
| task | 初始任务正文：任务 ID、角色、精简交接入口、开发目录及继承的权限/未决操作，不是仅填一个任务 ID |

脚本 --task 是协作任务 ID，--prompt-file 是启动正文；映射原生工具时，把 ID 放进 task 正文，不能把 --task 的值直接当作完整原生 task。模型由会话运行配置决定，不能给 create_session 补造 model/provider 参数。需要创建时明确选模则用项目支持的配置机制或 CLI 创建；若原生创建结果已知或未知，先查原执行，避免为换入口重复创建。

原生 `create_session.task` 的首次派发同样按 [消息协议](cli-routing.md#短消息协议) 添加 `[AgentMsg]` 和发送方 `[AgentSender]`，再附启动正文；不能用接收方稍后输出的 `[Session]` 替代发送方身份。脚本包装规则见 [创建指导](session-creation.md)，不把正文再做一次JSON字符串编码。

先整理当前状态，再调用创建工具取得真实继任 ID。继任读取自身角色、交接和项目要求，输出基础信息；按通用接力规则确认相关旧 writer 结束指定范围写入并移交写入权、移交在途操作、更新席位与 Owner，并通知管理者/相关方。创建对话和完成接管分别判断。

## talk_to_session 等待和投递

使用当前工具定义中的目标会话/联系人字段。真实 ses_... 与 contact_id 若属不同标识，按工具返回映射取得，不猜测转换。

当前反馈的行为是：mode=sync 最长约等待 120 秒；目标忙或外部 Agent 时可能自动转 async 并立即返回；异步消息到达后以标记消息回包；跨会话链路最多约 5 跳。这些是当前版本行为，不作为永久超时或拓扑规则，更新后以工具定义和返回说明为准。

- 普通交接通知按当前工具支持选择 async，避免无必要阻塞；需要直接答复且支持时才用 sync。
- sync 返回可能是异步受理，须读实际返回状态，不能把函数返回当已接收或工作完成。
- 超时/结果未知保留原消息和操作标识，等待回包或查原操作；未证明未投递之前不换 CLI 再发一次。
- 收到回包关联原消息，按当前席位/版本处理，无需 ACK 回 ACK。正式通信直接联系相关席位，减少中转；达到链路限制时报告实际阻塞，由负责管理者收敛路径，不自行绕行重派。

## 必要时核对真实 ID

可用当前支持的 mimo session list、mimo export <sessionID> 或只读会话元数据取得已有 ID。它们是身份不明确时的取证手段，不作为每次创建后的例行校验；App 可见性也不是开工门禁。
