# 执行控制与验证细则

这是按事件读取的参考，不是日常开发前置清单。日常工作从自己的角色页进入；发生下列情况时只读对应段。

| 当前情况 | 阅读段落 |
|---|---|
| 已授权派生子任务 | 第 2 段：唯一执行与写入归属 |
| 中断/结果未知、暂停或越界 | 第 3 段：中断与停止 |
| 自验对象不清或需固定交付证据 | 第 4、5 段：实际验证与版本 |
| 无增量循环或异步等待问题 | 第 6 段：止损 |
| 上下文膨胀、成本或迁移问题 | 第 7 段；真正换会话再读接力参考 |

审核失败计数及接管条件遵循用户/项目已确认规则，换会话不重置。所有执行继续遵守任务范围、现有授权和唯一 writer 约定。

## 2. 按需spawn，保持唯一执行与写入归属

- 已有委派授权时，writer可根据收益尝试spawn，不必逐个重复申请。适合输入输出明确的单项实现、独立检查或只读审查；小改动、接口尚不稳定或整合成本高时直接完成。主会话保留接口决策和最终整合责任。
- 从低并发开始，例如先用1–2个活动子代理；这是建议起点，不是所有项目的固定上限。同一共享worktree仍只允许一个实际代码写入者，主会话不能与受托者同时写；并行编码使用已授权的隔离环境，最后串行整合。
- 创建前记录唯一执行键（任务/阶段/子任务/修复轮次）、目标、输入版本、允许与禁止文件、验收；创建后补actor/operation ID和状态。沿用现有任务表或工具记录，不另建一套全局真源。
- 同一执行键只保留一个活动实例；结果未知时仍占用该任务和写入名额。重复消息去重，不另起同任务。方案比较可只读输出建议，不能让多个比较者竞争写生产文件。
- 公共模型、构建清单、测试入口和生成资源由指定整合者统一维护；各子任务依同一接口实现，不各自生成替代API。
- 子代理只做指定子任务，不自行接下一阶段或继续派生；需要再拆时由主会话统一判断和登记。主会话须能列出全部相关执行者及后代。
- 优先使用工具已有的限流、任务ID和权限隔离；无法控制写入范围时，改用只读建议或隔离副本补丁，由唯一writer应用。不能把提示词约束说成已有强制锁或幂等保障。

## 3. 中断、替代与暂停

替换工作包执行者先按 [撤任与授权流程](coordination.md#执行者替换先撤任再授权) 履行明确通知和释放确认。停止一次调用不是撤销旧会话的任务职责。

- 工具中断、超时或空回包表示结果未知，不证明任务未创建或已经失败。先用原actor/operation/session ID找回；缺ID时查创建记录或任务清单，不直接重派。
- 原执行仍活动则跟随；终态读取结果；只有证实旧执行不存在或已停止，且旧执行者该范围职责已解除或其写入能力已实际隔离，才允许冲突职责的替代。无法确认时保持未决，报告缺口，不启动冲突writer或绕过权限。
- 暂停须传到所有相关执行者及后代。cancel只是请求；通过工具终态且不再活动等证据确认停止后，才能移交写入权。文件暂时不变、SHA相同或旧回执均不能代替执行状态证据。
- 越界产物先停止写入，记录真实diff、注册入口和未完成点，保留并冻结；不自行删除、回滚、继续补齐或接入构建。由任务负责人决定处置，测试通过不等于范围已获准。

## 状态判断的证据范围

| 维度 | 依据 | 能说明什么 |
|---|---|---|
| 调用 | 原 operation/process ID、退出码及输出 | 该次调用结束/失败/未知，不代表整个会话退任 |
| 会话执行 | 当前客户端/服务实际回合、后代执行及活动证据 | 当前是否还有执行；CLI 日志可能看不到 Desktop 或其他入口启动的回合 |
| 工作包 | 当前交接中的版本、实现/冻结/取消等结论 | 交付与验收状态，不自动改变职责归属 |
| 职责与写入归属 | 撤任/承接通知、确认、当前 Owner 和实际隔离 | 当前谁有权继续该范围，区别于“进程暂时不存在” |

状态结论写明观察对象、时点与证据，例如“本次 CLI 已退出；会话撤任尚未确认”，不要合并为“开发者已停”。新消息或其他客户端重新启动回合后，旧的空闲/停止观察不再证明当前状态；以当前活动更新判断，不反复查询无变化的完整历史。进行接管时才核对相关入口，无需为每个普通消息新增全面扫描。

## 4. 验证实际交付，避免无增量回归

- 修复先明确失败条件、对应生产路径和预期结果，做针对性复现；修根因，不为绕过审查整体换实现。
- 验证实际源码和集成边界：公共接口看真实编译单元及调用者；生命周期看实际入口与状态转换；生成资源在隔离副本执行再生。纯模型、常量或工具自述不能代替实际运行路径。
- 先完成受影响的最小检查，送审前再跑约定的必要回归。同版本、输入、环境且无新疑点，不重复全套检查；相关源码、公共接口、构建或测试入口改变后重跑受影响集合。
- 检查失败须修复或如实报告，不删检查、不忽略退出码、不用固定成功掩盖业务失败。构建、设备和外部操作仍按已获权限执行，未执行明确写出。
- 主会话检查子代理的实际diff、文件范围、接口、验证证据和副作用后才整合，不能仅转述“子代理已通过”。测试数量不等于覆盖度，主机通过不等于设备或线上通过。
- 并行只读检查可提前发现问题，但活动writer仍在修改时的检查结果不能直接作为固定交付版本的验收证据；最终证据须对应送审版本。

## 5. 冻结待审与快照

冻结是工作包版本约束，由管理者接续审核；通过后续派下一项授权工作。真实任务暂停和写入权移交按 [生命周期](task-lifecycle.md) 区分，不单独用“停写”作为任务结论。

- 送审/投递是独立单次步骤：准备（报告、清单、SHA、日志）可重跑，queue/发消息等副作用动作不得混入可重放脚本或整段回复。每完成一步立刻落状态，中断恢复时先读状态决定续跑点，禁止整段重放含副作用的块。结果未知≠失败：先查现场（台账、日志、CLI输出）再决定，不假设未送达。
- 顺序：最后编辑（含生成与格式清理）→相关验证→确认全部相关writer结束该范围修改→固定交付版本→送审。已提交用commit标识；未提交按任务要求给完整文件清单及SHA或等价可核对快照。
- 快照覆盖实际改动，含公共头、生成脚本/原件/输出、构建清单及测试入口，不只列核心源码。生成物与来源/脚本必须匹配。
- 快照后任何编辑先声明旧快照作废；重跑受影响检查，再发关联原交付的新版本。不沿用旧PASS，不把摘要更正自动算作新一次代码审核失败。
- 交付简明写：改动及问题映射、版本与冻结范围、实际检查结果、未验/越界项和证据位置。不反复复制已冻结阶段全文。
- 消息遵循技能入口的短格式：正文只报本轮增量，完整清单/SHA与检查日志留可访问证据文件；无需每条附身份、目录、分支和历史禁令。接收方无法访问文件时才补足必要内容。

## 6. 循环止损与消息纪律

- 每次工具调用应回答一个会影响下一步的问题。相同版本检查连续两次同输出时，停止第三次无增量重复；转为针对性修改、补输入、读取不同的相关证据或报告阻塞。
- 连续三次调用没有新增证据、改动或有效状态变化时，先收敛“目标、已知、缺口、下一动作”，再执行有依据的一步。这些是防循环参考阈值，不替代工具要求的必要轮询或取证。
- 遇到平台循环告警立即结束当前重复链；再次发生则报告该片段停点，不靠重复spawn绕过。可在已有权限和并发额度内安排一次有界只读诊断，不能复制冲突实现。
- 异步操作跟随原执行，优先事件通知或有界等待，日志只读增量；不并发恢复同一会话来催进度。确认、接收、运行、完成按实际证据区分。
- 消息去重与路由遵循技能入口。无新状态不重复ACK或“马上开始”；权限拒绝后不原样循环投递，用已约定可用路径交付并说明未送达，不加权限跳过参数。

## 7. 上下文与交接

- 主会话保留精简当前状态：目标/禁令、owner及执行者、实际版本、未决问题、验证证据位置、下一动作。历史日志按需引用，不每轮附完整会话。
- 子代理接收必要文件、接口和一页任务上下文，不复制无关历史；利用客户端摘要能力。出现持续遗忘或重复执行时先整理交接，再按授权决定迁移，不按消息条数机械新建。
- 开发者和其他角色均可自主创建自身接力，按协作协议转移 Owner、登记并通知；子任务执行者不能据此替换所属管理者。不能借迁移清除未决状态、跳过写入权移交确认或重置审核计数。
- 如报告成本，注明统计来源和口径，区别输入/输出/缓存读取、重试与时间窗；未核验数据不推导账单或实际收益。

协调者派发应给清楚边界和有用途的验收集合，一次合并同轮意见；结果未知先核对原操作，不因迟到回执重派，不对确认再确认。
