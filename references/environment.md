# 项目配置与环境适配

仅在建立项目协作、个性化配置变化、工具/模型变更或现有方法失效时读取；正常开发不必预加载。

## 采用哪份约定

用户当前明确指令优先；其次遵守项目 AGENTS 与 HANDOFF 中的协作约定，再采用本技能默认值，同时遵守系统和工具强制约束。项目文档冲突时先查明确的真源或较新的已确认决定；无法判断则只澄清影响当前动作的一项。

项目可直接在 HANDOFF 写简短“协作约定”：角色的 Agent/模型偏好、创建与通信方法、任务粒度、资源/并发限制、汇报偏好、操作授权以及本地配置入口。无需为此新增固定配置格式。共享文档保留可移植规则和模型/工具偏好；绝对机器路径、实例地址、凭据及真实会话绑定留本地记录，密钥不回显。

个性化配置应明确具体偏好，缺省项继续用技能规则；默认非 TDD，项目明确写出采用 TDD 时才启用。普通实现任务仍以已裁决范围和验收为准，不因工具附带流程技能重新展开研发流程。

## 选择当前可用方法

角色不绑定厂商或模型。根据本次可调用工具、项目配置和当前客户端帮助，选择满足同一任务的受支持方法；现有 Codex/MiMo 名称只是默认适配示例，其他 Agent 可用等效能力。

同产品优先使用原生独立会话/通信能力；不可用、已更名或跨产品时使用当前支持的等效工具或 CLI。只核对会影响执行的参数和真实目标，不做例行 App 可见性或双端探测。配置优先选择模型；未找到适用模型时省略模型参数，交客户端默认，保留实际选择及回退原因。

方法回退保持原任务、目标席位、目录与已获权限。只有能确认原操作未执行或已明确失败时才换路重做；结果未知先追踪，避免一条消息或一次创建被执行两次。需要新产品适配或当前脚本参数已失效时，按真实接口调整调用，不伪造字段、模型 ID 或扩张权限。
