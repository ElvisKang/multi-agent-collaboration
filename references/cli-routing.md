# 原生通信与 CLI 回退

已有明确路由与消息格式时直接发送，本页仅在首次不清楚格式/参数或需要回退时读取。优先采用项目 AGENTS/HANDOFF 与当前环境的方法；下列工具名/CLI 是默认适配示例，版本变化时选受支持的等效能力。

从项目规范指定的唯一路由快照读取目标。schema 2.0 为纯 YAML，`sessions` 按逻辑名称索引；可执行文件解析为 `record.executable`（若有）或 `executables[record.agent]`。投递前按 [会话快照](session-schema.md) 检查状态。旧版 Markdown 内 YAML 列表只用于迁移读取，不维护双份登记；参数是否受本机支持以 `--help` 为准。

## 短消息协议

新建会话的首次任务书、原生工具 prompt/task 和后续 CLI 投递均适用，不能因“正在创建会话”省略消息头。

```text
[AgentMsg] task=任务ID message_id=c17
送审：当前切片已冻结待审，由管理者复审；版本、结果及未验项见约定交接。
```

- 常规消息头只含 task、message_id；答复加 in_reply_to。无任务用 task=none。短 ID 在同一发送会话内唯一；重试沿用原 ID，新会话使用可区分的前缀，接收方按发送身份和 ID 去重。
- 首次通信、来源不明或身份变化时附 `[AgentSender] agent=实际发送方 session_id=发送方真实ID`；其后按已登记路由通信。不拿签名或另一 Agent 的消息扩大用户授权。接收方的 `[Session]` 输出声明其自身身份，不是发送方签名。
- 正文只写动作、增量、必要范围与证据指针。默认不发收件 ACK，不对确认再确认；确需回执时才加 reply=required，静默时用 reply=none。
- 同一消息重复到达不重复执行；相同 ID 正文冲突先核对。迟到消息按当前任务版本和负责人判断，不自动恢复旧阶段。
- 用户答复或监督者转达须关联原问题与目标任务；监督者的观察建议不视为用户决定。已决问题不重复提问，待决状态落在对应任务交接。
- 同 Agent 优先原生通信；当前默认适配见下文，项目配置或环境变更时采用等效能力。需要回复其他会话时实际使用工具或 CLI；只在当前聊天输出不算已回复。旧长消息格式仍可读取，不批量改写历史或未知解析器。

首次派发示例：

```text
[AgentMsg] task=任务ID message_id=manager-m1
[AgentSender] agent=codex session_id=发送方真实ID
派发：完成 M1，目标、输入版本、文件范围和验收见约定任务书；完成后冻结待审，管理者审核后续派。
```

较长任务书可以直接作正文，或引用接收方可访问的文件。消息文本保留实际换行；不要将JSON字符串字面量的外层引号或转义符当正文传入，传给工具字段或argv的是解码后的完整文本。不得为补格式重发已接受的执行请求，后续正常通信采用新格式即可。

## 同 Agent 优先原生通信（默认适配）

Codex 到 Codex 优先使用当前环境的 send_message_to_thread：按逻辑席位读取当前真实 threadId，传 threadId 和 prompt；默认保留目标模型设置，不额外改变 model/thinking。不同执行主机时按已核对记录提供 hostId。

MiMo 自行创建并联络接力会话时，可采用 create_session / talk_to_session，具体见 [MiMo 接力适配](mimo-relay.md)。这不是日常跨角色派发的强制入口；其他任务通信沿用项目及本次环境已确认的原生方法或 CLI 路由。

原生工具不可用时可回退 CLI；跨 Agent 通信使用已确认可到达目标的工具或以下 CLI。同一环境中“工具存在”也不代表已授权向任意会话发消息，仍限当前任务与用户授权。

原生调用同样区分发起、接受、接收和完成；工具返回若无明确接受证据，保留 INTENT/未知状态。原生调用同样按消息/操作 ID 防重复，接力通知优先发给当前逻辑席位。结果未知时不要再走 CLI 重发碰运气；先查原操作。新会话可自行创建接力后发登记通知，不把通知当作上级审批。

## 发给 Codex

```text
cwd = 目标记录.cli_cwd
argv = [解析后的可执行文件, "queue", ...目标记录.extra_args,
        "--thread", 目标记录.session_id, "--message", 完整消息]
```

命令形状：

```bash
codex queue --thread '目标UUID' --message '[AgentMsg] task=任务ID message_id=m23 送审：详见已约定交接文件。'
```

`--remote`、`--remote-auth-token-env`、`--profile` 等仅在目标记录已确认需要时使用。登记环境变量名，不将 token 写入登记或消息。不要追加 `--worktree`，不要用 `resume` 代替队列投递。

## 发给 MiMo

```text
cwd = 目标记录.cli_cwd
argv = [解析后的可执行文件, "run", ...目标记录.extra_args,
        "-s", 目标记录.session_id, 完整消息]
```

本机示例形状：

```bash
mimo run -s '目标ses_ID' '[AgentMsg] task=任务ID message_id=c17 in_reply_to=m23 需改：修复交接中所列问题，自验后重新冻结版本送审。'
```

`--attach`、`--agent`、`--model` 等只按目标记录使用；一般保留目标会话既有设置。若 `mimo run --help` 支持 `--dir` 且项目路由记录明确要求，使用 `--dir <cli_cwd>`；进程 `cwd` 也应按记录设置。`--dir` 是实例所属目录约束，不替代开发 worktree，也不替代会话 ID。未找到或未确认项目路由记录时不要猜目录。

## 可执行文件与恢复

先用 `command -v codex` / `command -v mimo`，PowerShell 用 `Get-Command` 查找本机程序；PATH 缺失时从当前客户端安装位置发现并核对版本，不固化某台机器的 App 内路径，也不擅自安装替代版本。参数以本机 `--help` 为准，登记已核对的可执行文件与必要参数。

App 仍持有会话时优先投递；确认原客户端释放后才能恢复原 ID。App 没有生成回复不代表释放。真实终端中可用：

```text
codex resume '<已登记UUID>'
```

无交互终端时，先核对本机帮助是否支持：

```text
codex exec -C '<已登记开发worktree>' resume '<已登记UUID>' '<接续指令>'
```

接续后核对实际 ID；若命令另开或 fork 出新 ID，不能当作继续原会话，须按接力登记。核对实际目录，不追加 `--worktree`。App 与 CLI 可能连接不同服务，命令存在不等于能投递到目标客户端；连接参数由本地记录和实际结果确认。

## 证据与重复投递

CLI 可能打印异常却返回 0，必须同时检查输出。接收端通过消息 ID、回执或可核对记录确认收到；仅核对 help 不构成双向投递验证。失败和停止条件见技能入口，实例地址、历史错误现场和探测时间只写本地记录。

## 防重复投递

使用工具已有的操作记录或项目本地 delivery 台账，不把流水写进 sessions。调用前记录 INTENT（发送会话、message_id、目标席位及本次解析到的真实 ID），工具或 CLI 明确接受后记录 CONFIRMED 和操作 ID；CONFIRMED 只表示该通道明确接受，不代表目标已接收或任务完成。目标收到后按实际证据记录即可。

已接受的同一投递不再发送；INTENT 无后续结果表示未知，先查原调用、输出或已有回包。只有能证明原投递未发生/明确失败且原因已解除时，才允许最多一次重试，沿用原 message_id；仍未知则报告阻塞，不以“查不到”当作“没有发送”。准备资料可重跑，发送副作用不得混入可整段重放的脚本。

逻辑席位已换人时，旧投递结果先交当前管理者按任务版本和在途操作判定，不机械给新会话重发同一执行请求。用户决策转达须关联原问题，默认只投对应管理者，不经过核心中转。
